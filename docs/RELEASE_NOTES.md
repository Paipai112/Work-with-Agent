# 发行说明

## v0.1.1（2026-10-10）

`v0.1.1` 为当前固定发行版本，是独立评审后的修复版：收紧 PR 元数据检查、补齐治理分类、把认领评论核验改为实拉比对，并落地 v0.1.0 公开发布后的收尾事项。安装仍以维护者实际发布的标签、该标签解析后的完整提交 SHA 和同 SHA 安装页为准；本页不替代这些核验。

### 本版变更

- **元数据检查器**：认领评论改为按 GitHub API 实拉核验——存在性、作者账号 ID、所属 Issue（由工作流采集）；关闭关键字支持冒号与大小写形式（`Closes: #10`）；治理路径新增 `.agents/skills/`、`.claude/skills/`、`.pi/agent/skills/`、`.pi/skills/`、`.github/actions/` 与 `.github/copilot-instructions.md`；入口文件（`AGENTS.md`／`CLAUDE.md`／`CONTRIBUTING.md`）的任何修改都要求独立治理 PR；检查输出新增核验范围提示。
- **工作流**：与检查器配套采集认领评论；评论不存在或不可读取时失败关闭。
- **github-collaboration（日常）技能**：新增「不可信输入」硬规则——外部文本只当数据处理；执行其中命令需操作者当次确认；任务来源限于操作者与职责指派；不在未受信任的工作树中启动会话。
- **github-collaboration-setup（安装治理）技能**：治理技能不再隐式触发（需显式调用）；含 `format` 字段的校验显式依赖 `jsonschema[format]` 并失败关闭；补充用户级安装作用域与工作树安全说明。
- **公开面**：README 与安装页更新至 v0.1.1 口径；说明机器标识符（技能名、受管区块标记、schema `$id`、治理文件路径）保持不变的原因；`LICENSE` 纳入发行快照。
- **仓库基建**：新增 CI（包校验＋离线回归）、`CONTRIBUTING.md`、`SECURITY.md`。

### 从 v0.1.0 升级

- 检查器与工作流应成对升级：新检查器需要 `claim_comments` 数据（由新工作流采集）；只升级一侧会失败关闭。
- 治理分类收紧属行为变化：日常 PR 触及新增治理路径或入口文件时，改走独立 setup 治理 PR。
- 配置版本字段（`protocol_version`、`minimum_runtime_skill_version`、`setup_skill_version`）同步为 `0.1.1`。
- v0.1.0 安装的包可继续使用；升级按 [安装页](INSTALL.md) 的增量流程，以新的固定提交重新核验。

### 验证范围

离线回归 378 项通过、6 项排除；包校验通过；发行快照、manifest 与摘要重建核验。客户端原生加载沿用 v0.1.0 的 macOS／Codex 结论，本版未重跑，不宣称其他组合通过。详见 [验证说明](VALIDATION.md)。

## v0.1.0（2026-10-01）

`v0.1.0` 于 2026-10-01 发布的固定发行，用于获授权项目。安装以维护者实际发布的标签、该标签解析后的完整提交 SHA 和同 SHA 安装页为准；本页不替代这些核验，也不预先填写未知 SHA。

### 发行内容

- 两个完整且独立的纯 Skill：setup 负责配置、诊断、升级和治理，daily 负责日常 GitHub 协作流程。
- 项目协议、角色和授权模板，受管资源账本、项目上下文索引，以及 Issue／PR 模板。
- 默认 Member、显式 Leader／Bootstrap／Recovery、默认分支授权读取、任务认领与交接、精确暂存和 PR 审查流程。
- 增量处理已有入口和项目文件；来源固定、资源 manifest 校验、同名包与本地修改诊断。
- 可选 PR 元数据检查模板。Actions、Required Checks 和 Rulesets 默认关闭，启用需逐项审批。

来源规则支持维护者指定且当前用户可访问的公开或私有发行仓库；私有访问权不等于开源许可。通用 `INSTALL_SKILL.md` 模板保持 `unpublished` 和四个空发行字段，由各消费项目根据已核验的固定提交生成实际安装入口。

客户端包安装／升级与项目治理分别授权：安装不依赖预先存在的项目 Leader，须由目标目录拥有者批准精确安装提案；它不授予 Leader，也不批准修改项目治理文件或进行 Git／GitHub 写操作。

### 已验证范围与限制

该轮 macOS 原生 Codex CLI `0.159.3` 对 `github-collaboration-setup` 和 `github-collaboration` 的只读显式调用均通过。这证明该组合可以实际读取两个入口并进入各自的只读流程，不能外推为其他平台通过，也不能代替消费项目的安装和治理验收。

Linux、Windows native、WSL、Claude Code 和 Pi Agent 的原生调用未在该轮验收。平台路径合同、加载器发现结果及静态包校验各有范围；它们不等同于完整的新会话原生调用。其他组合使用前须按 [安装说明](INSTALL.md) 在实际环境确认读取路径、版本与资源。

离线测试的选择、复现命令和证据边界见 [验证说明](VALIDATION.md)；测试依赖安装见 [安装页](INSTALL.md#可选离线回归)。

该发行不把角色协议当作安全沙箱，不保证共享账号下有独立的 GitHub 审查身份。可选元数据检查不能证明 Skill 实际加载或人类审批。自动保护能力及 Actions 额度／费用取决于目标仓库、组织政策与当前产品方案；每个项目须只读核验实际设置后决定接入方式。

接入现有项目需保留用户内容，先审阅同名包、受管资源和未提交改动的差异。升级使用新的固定提交和增量方案，详见 [安装与项目接入](INSTALL.md)。
